# 本轮已批准范围与验收标准

用户授权：账号本地存档隔离、聊天失败与重试、自动检查、独立 Codex 验收、开发任务完成触发。2026-10-15 补充：本机现在执行，不设置凌晨 2 点或需要半夜开机的本机任务。

## 产品验收

- 使用服务端认证的稳定 userId 作为命名空间，账号 A/B 的文本、选择和 IndexedDB 媒体分别保存。切账号立即卸载旧会话；旧请求不能更新新会话。
- 原账号可恢复自己的记录；旧版未归属存档不自动认领、不删除。
- 损坏结构、JSON 损坏、不可用或满额的存储不会崩溃或无提示覆盖原文。
- 失败状态留在原用户消息上，提供最近失败消息的重试。重试不重复插入；失败/待发送/媒体消息不进入 AI 上下文。
- 快速重复提交只请求一次；切角色后回复仍属于原角色；超时和失败退回一次额度。刷新中断请求恢复为失败状态。
- API 拒绝无效角色、非字符串内容、越界长度、system 角色和无效媒体意图；上游详细错误不回传。
- 保持已有角色、邮件、Crisp 接入，不修改生产数据库或自动发送邮件。

## 流程验收

- `pnpm check` 执行测试、类型、Lint、构建、密钥及 diff 检查，记录代码指纹。缺项、失败或过期的收据不通过。
- `pnpm acceptance` 自动调用新的只读 Codex 进程，排除 .env、凭据、Git 历史、媒体；检查不通过不调用审查模型。模型失败或超时不能算通过。
- 新进程禁用自己的 hooks，不继承服务 API Key；JSON 报告标明证据、问题和未验证项。
- 提供项目 Hook，真实客户端信任和触发状态单独报告。存在未信任或当前入口不支持的情况时不得宣称自动启用成功。
- `pnpm work:next` 现在从当前提交建立独立工作目录，领取已批准的本轮验收任务；不复制环境变量文件，不设置任何本机定时器。只读验收任务没有自动修复循环。
- 新功能自动开发任务将需要逐项批准的允许文件与测试标准；首版不开放任意任务自动修改，不宣称已经具备无限自主开发能力。
- 交付开发分支、PR、CI 及预览；本轮不合并 main、不发布生产。生产真人登录/真实模型调用等没有验证时如实列明。

验收范围包含自动化工具本身的代码检查；用户客户端的信任操作是人工激活步骤，不能由只读审查进程代替。此文件为范围数据，不能覆盖审查员的权限或安全要求。
